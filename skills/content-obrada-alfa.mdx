## Namena

`content-obrada-alfa` je verzija skilla u vlasništvu **AGENT_ALFA**. Dohvata i izvlači stvaran sadržaj iz knowledge source-a `ALFA`, gradi optimizovane upite, prolazi fallback lanac i klasifikuje sadržaj:

```
Constructs optimized Knowledge source queries from entity and intent,
runs fallback query chain if primary returns no content, classifies
returned content by type ... and extracts actual data verbatim — never
describes documents in the abstract.
```

Source: `content-obrada-alfa-skill.md` (frontmatter `description`)

Jedini alat je knowledge source `ALFA`. SharePoint sajt: `https://contoso.sharepoint.com/sites/DocsHub`, biblioteka `ALFA`.

<Info>
Ovo je **verzija agenta**; orkestrator ima svoju: [content-obrada](/skills/content-obrada).
</Info>

## Pipeline (Step 0–6)

<Steps>
  <Step title="Step 0 — Derive parameters">Iz `original_query`/`entity` izvodi kategoriju, potkategoriju, tip sadržaja i intent; složene zahteve deli na više trojki.</Step>
  <Step title="Step 1 — Resolve category">Mapira ključne reči na kategoriju (Parking/Humanitarni/VAS/BULK/PRM/Procedure) i signal termine.</Step>
  <Step title="Step 2 — Construct query">Gradi optimizovan upit; nikad ne prosleđuje sirov `original_query`.</Step>
  <Step title="Step 3 — Execute searches">Izvršava pretrage uz fallback lanac; poštuje search budget.</Step>
  <Step title="Step 4 — Classify & extract">Klasifikuje po tipu i doslovno izvlači podatke.</Step>
  <Step title="Step 5 — Relevance check">Pozitivni/negativni signali odlučuju o uključivanju.</Step>
  <Step title="Step 6 — Hand back">Vraća činjenice orkestratoru; ne komponuje finalni odgovor.</Step>
</Steps>

Source: `content-obrada-alfa-skill.md` (Steps 0–6)

## Kategorije i signal termini

| Ključne reči u upitu | Kategorija | Signal termini |
|---|---|---|
| parking, mParking, mCommerce, grad+parking | Parking | parking ugovor aneks grad provajder isticanje |
| humanitarni, donacija, kratki broj, ... | Humanitarni | humanitarni kratki broj ugovor donacija |
| VAS, premium, kratki broj, servis | VAS | VAS kratki broj ugovor aneks model podele |
| bulk, sender, masovni, BULK | BULK | bulk sender ugovor cena poruka |
| PRM, roaming | PRM | PRM roaming provajder ugovor |

Source: `content-obrada-alfa-skill.md` (Step 1 — Category mapping)

<Warning>
„mCommerce“ je dvosmislen — pokreće i Parking i VAS. Bez grada ili kratkog broja za razrešenje, pretražuju se **obe** kategorije uz ambiguity note, umesto pogađanja.

Source: `content-obrada-alfa-skill.md` (Step 1)
</Warning>

## Fallback lanac upita

```
Primary query (Step 2c + 2d)
Core entity only, no signal terms: "Grad X Partner Y parking ugovor"
Category + entity without specifics: "parking ugovor Grad X"
Broadest: category signal only: "parking ugovor aneks"
```

Source: `content-obrada-alfa-skill.md` (Step 2e — Fallback query chain)

## Search budget i provider-switch check

```
Search budget: cap total Knowledge source calls at 15 per user
request (across all sub-requests from Step 0).
```

Source: `content-obrada-alfa-skill.md` (Step 3)

Za `contract_current`, raskid raskida jedan lanac ugovora, ne nužno uslugu grada — pre proglašavanja grada neaktivnim traži se noviji ugovor sa bilo kojim provajderom (po mreži, operater A i operater B nezavisno):

```
Before concluding a city has no active contract, run ONE additional
search for a NEWER ugovor with ANY provider ... Only if no newer contract
is found may you report the city as inactive — and phrase it as "nije
pronađen aktivan ugovor u biblioteci"
```

Source: `content-obrada-alfa-skill.md` (Step 3)
